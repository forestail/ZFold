# zfold 使い方ガイド

## 1. zfold とは

`zfold` は、ディレクトリをまとめて 1 つのアーカイブファイルにするためのコマンドラインツールです。

単に「ファイルを 1 個にまとめる」だけではなく、次のような用途を想定しています。

- 小さいファイルが大量にあるディレクトリを、できるだけ効率よく圧縮したい
- Web サイトの配布物、設定ファイル群、ログやテキスト資産をまとめて保存したい
- 定期バックアップやスナップショットを、後から一覧表示、検証、展開したい
- 必要ならパスワード付きでアーカイブ化したい

作成されるアーカイブは通常 1 つの `.zpk` ファイルです。

---

## 2. 何ができるか

`zfold` には主に次のコマンドがあります。

- `zfold pack`
  - ディレクトリをアーカイブにまとめる
- `zfold list`
  - アーカイブの中身を一覧表示する
- `zfold extract`
  - 必要なファイルを取り出す
- `zfold verify`
  - アーカイブが壊れていないか、内容が一致しているかを検証する
- `zfold train-dict`
  - 圧縮率を上げるための辞書ファイルを作る

---

## 3. 基本の使い方

### 圧縮する

```powershell
zfold pack ./dataset -o dataset.zpk
```

### 中身を見る

```powershell
zfold list dataset.zpk
```

### 展開する

```powershell
zfold extract dataset.zpk -d ./out
```

### 整合性を確認する

```powershell
zfold verify dataset.zpk
```

---

## 4. zfold の圧縮方法の特徴

### 普通の ZIP と何が違うのか

多くの ZIP ツールは、基本的に「各ファイルを 1 個ずつ別々に圧縮」します。

たとえば次のようなファイルが 1,000 個あるとします。

- よく似た HTML
- よく似た JSON
- よく似た設定ファイル

ZIP では、各ファイルが別々に圧縮されるため、ファイルをまたいだ似たパターンを十分に活かせないことがあります。

一方 `zfold` は、複数ファイルをチャンクというまとまりにしてから、そのまとまり全体をまとめて圧縮します。（「Solid Archive 的な圧縮」）

つまり、`zfold` は次のように動きます。

1. ファイルを集める
2. ある程度の大きさごとにチャンクに分ける
3. チャンク全体をまとめて zstd で圧縮する
4. それを 1 個のアーカイブに書き込む

この方式の利点は、似た内容の小さいファイルが多いと圧縮率が上がりやすいことです。

### zfold が得意なデータ

- HTML
- CSS
- JavaScript / TypeScript
- JSON
- XML
- テキスト設定ファイル
- CSV やログ
- 似たテンプレートから生成された大量の小ファイル

### zfold があまり得意でないデータ

- すでに圧縮済みのファイル
  - JPEG
  - PNG
  - MP4
  - ZIP
  - gz
- 内容がバラバラで共通性が少ない大きなバイナリ

こうしたデータでは、ZIP と比べて圧縮率の差が小さいことがあります。

## 5. zfold の長所と注意点

### 長所

- 小さいファイルが大量にあるときに強い
- 似た内容が多いほど圧縮率が上がりやすい
- `zstd` を使うため、速度と圧縮率のバランスがよい
- `verify` で内容検証ができる
- 必要なら暗号化できる

### 注意点

- 1 ファイルだけ取り出したくても、そのファイルが入っているチャンク全体を一度展開する必要がある
- ZIP のような「各ファイル完全独立」ではない
- `--threads` や `--chunk-size` を大きくしすぎると、圧縮時のメモリ使用量が増える

特に最後の点は重要です。`zfold` は圧縮時に各ワーカーがチャンク 1 個分の未圧縮データをメモリ上に組み立ててから圧縮します。大量データを扱うときは、`--threads` と `--chunk-size` を控えめにすると安定しやすいです。

---

## 6. チャンク

`zfold` では、複数ファイルをある程度のサイズで区切って「チャンク」にまとめます。

たとえば `--chunk-size 16777216` なら、目標として約 16 MiB ごとにチャンクを作ります。

ここでのポイントは 2 つです。

- これは目標値であって、絶対上限ではない
- 単一の大きなファイルは、それだけで大きなチャンクになることがある

### チャンクサイズを大きくすると

- 圧縮率が少し良くなることがある
- その代わりメモリ消費が増える
- 一部展開時に読む量も増えやすい

### チャンクサイズを小さくすると

- メモリを抑えやすい
- 一部展開の無駄が減りやすい
- 圧縮率は少し下がることがある

迷ったら、まずは既定値で試し、メモリが厳しい環境では次のようにします。

```powershell
zfold pack ./dataset -o dataset.zpk --threads 1 --chunk-size 8388608
```

## 7. 辞書ファイル

### 辞書ファイルの役割

`zstd` には「辞書圧縮」という仕組みがあります。

これは、よく出てくる文字列やバイト列のパターンを事前に学習しておき、その知識を使って圧縮する方法です。

たとえば次のようなデータでは効果が出やすいです。

- HTML の共通テンプレート
- 同じキー構造を持つ JSON
- よく似た設定ファイル
- 共通のヘッダや定型文を持つログ

こうしたデータは、1 ファイルごとのサイズが小さいほど普通の圧縮では不利になりやすいのですが、辞書があると改善しやすくなります。

### 辞書を使うメリット

- 小さいファイル群の圧縮率が上がりやすい
- 共通パターンの多いデータで特に効く
- 同じ種類のデータを何度もアーカイブ化する場合に有利

### 辞書が効きやすいケース

- 似た JSON を大量に持っている
- Web 配布物の HTML/CSS/JS を毎回固める
- アプリ設定、INI、TOML、YAML などの小ファイルが多い
- 似た構造のテキストログが大量にある

### 辞書が効きにくいケース

- 画像、動画、音声
- 既に圧縮済みのデータ
- データの種類がバラバラで共通点が少ない場合

### 辞書を使う場合の挙動

`zfold pack --dict <DICT_FILE>` で辞書を指定すると、その辞書はアーカイブの中にも埋め込まれます。つまり、展開側が別途辞書ファイルを持っていなくても、そのアーカイブ単体で解凍できます。

これは運用上かなり便利です。

- 辞書を別配布しなくてよい
- 「解凍時に辞書がない」という事故が起きにくい
- アーカイブごとに使った辞書を閉じ込められる

## 8. 辞書ファイルの作り方

辞書は `train-dict` で作れます。

```powershell
zfold train-dict ./snap1 ./snap2 ./snap3 -o app.dict --mode text
```

これは複数の入力ディレクトリからサンプルを集めて、似たデータ向けの辞書を作るコマンドです。

### 重要な考え方

辞書は「これから圧縮したいデータに似たサンプル」で作るのが重要です。

たとえば、設定ファイルを圧縮したいのに、画像だらけのディレクトリから辞書を作ってもあまり意味がありません。

### 実用的なコツ

- Web 資産なら HTML/CSS/JS/JSON を中心に学習する
- 設定ファイルなら `ini`, `toml`, `yaml`, `json` などに寄せる
- まずは `--mode text` を使う
- ファイル種別を絞りたいなら `--extensions` を使う
- 特定ディレクトリだけを使いたいなら `--include` を使う

例:

```powershell
zfold train-dict ./app -o app.dict --include "config/**" --extensions ini,json,toml,yaml
```

---

## 9. 辞書を使うとどれくらい良くなるのか

圧縮率の改善と同時に、圧縮速度・伸長速度も速くなりますが、効果はデータ次第です。固定の数字はありません。

傾向としては次の通りです。

- 小さくて似たファイルが多いほど効果が出やすい
- 大きな単一ファイルでは差が小さいことがある
- 圧縮済みデータではほとんど効かないことがある

特に「1 ファイルごとのサイズが小さい」「でも中身は似ている」という状況では、辞書の有無で体感差が出やすいです。

たとえば次のようなケースは相性が良いです。

- 数 KB の JSON が何万個もある
- HTML の静的生成物が大量にある
- 似たログ断片や設定断片が大量にある

逆に、画像や動画が中心のディレクトリでは辞書を作る手間に見合わないことがあります。

## 10. ZIP と比べたときの採用基準

### zfold を選ぶとよい場面

- 小さいファイルが大量にある
- ファイル同士がよく似ている
- アーカイブ全体の圧縮率を重視したい
- 定期バックアップや配布物の固め直しをしたい
- 辞書を使ってさらに詰めたい

### ZIP を選ぶとよい場面

- 誰でもすぐ開ける汎用形式を優先したい
- 1 ファイル単位で独立した取り出しやすさを重視したい
- 既に圧縮済みファイルが中心で、圧縮率差があまり期待できない

要するに、`zfold` は「汎用交換フォーマット」というより、「似た小ファイル群を効率よくまとめ、コピーやバックアップを取りやすくする専用ツール」と考えると分かりやすいです。

## 11. パスワード保護

`zfold` はパスワード付きアーカイブも作れます。

```powershell
zfold pack ./dataset -o secure.zpk --password-prompt
```

暗号化されるのは主に次の部分です。

- チャンクデータ
- 埋め込み辞書
- バイナリ index

一方で、ヘッダとフッタは平文のままです。これは、ツールがアーカイブ形式や暗号化有無を先に判断するためです。

運用上は、`--password` でコマンドラインに直接書くより、`--password-prompt` や `--password-file` のほうが扱いやすいです。

---

## 12. 壊れていないか確認したいとき

`verify` を使うと、アーカイブの構造や CRC32 を確認できます。

```powershell
zfold verify dataset.zpk
```

これは単なる「ファイルが読めるか」だけでなく、各ファイルの中身が一致しているかも検証します。

バックアップ用途では、作ったあとに `verify` を回す運用が実用的です。

---

## 13. よくある使い方

### 1. とりあえずまとめる

```powershell
zfold pack ./project -o project.zpk
```

### 2. 低メモリ環境で安全寄りに圧縮する

```powershell
zfold pack ./project -o project.zpk --threads 1 --chunk-size 8388608
```

### 3. 辞書を作ってから圧縮する

```powershell
zfold train-dict ./snap1 ./snap2 ./snap3 -o app.dict --mode text
zfold pack ./project -o project.zpk --dict app.dict
```

### 4. 一部だけ取り出す

```powershell
zfold extract project.zpk -d ./out --prefix "docs/"
```

---

## 14. まとめ

`zfold` は、似た小ファイルがたくさんあるディレクトリを、効率よくまとめて保存するのに向いたツールです。

ポイントは次の 3 つです。

- ZIP のように各ファイルを別々に圧縮するのではなく、チャンク単位でまとめて圧縮する
- そのため、小さいファイルが大量にある環境で圧縮率が良くなりやすい
- 辞書ファイルを使うと、共通パターンの多い小ファイル群でさらに効果が出やすい

迷ったら、まずは辞書なしで使い、効果が欲しいデータ群に対してだけ辞書を導入するのが現実的です。
