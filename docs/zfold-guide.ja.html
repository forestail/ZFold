zfold 使い方ガイド

zfold は、似た小ファイルがたくさんあるディレクトリを、効率よく .zpk アーカイブへまとめるためのツールです。ZIP との違い、辞書ファイルの意味、 使いどころ、設定の考え方まで、初めて触る人にも分かる形で整理しました。

solid archive 的な圧縮 zstd + 辞書圧縮 小さい類似ファイル向き

01

zfold とは

ディレクトリを 1 つのアーカイブにまとめるコマンドラインツールです。単なる「固める」だけでなく、 小さい類似ファイル群を効率よく圧縮して保存することに向いています。

向いている用途

  • 小さいファイルが大量にある
  • 内容が似たファイルが多い
  • スナップショットやバックアップをまとめたい

できること

  • 圧縮して 1 つにまとめる
  • 一覧表示する
  • 展開する
  • 壊れていないか検証する

生成されるもの

  • 通常は .zpk ファイル 1 つ
  • 辞書を使う場合もアーカイブ単体で解凍できる
  • 必要なら暗号化もできる
02

何ができるか

zfold には、運用に必要な基本コマンドが揃っています。

zfold pack

ディレクトリをアーカイブにまとめます。

zfold list

アーカイブの中身を一覧表示します。

zfold extract

必要なファイルを取り出します。

zfold verify

アーカイブ構造と内容が壊れていないかを確認します。

zfold train-dict

圧縮率を上げるための辞書ファイルを作ります。

03

まずは一番基本の使い方

最初は辞書なし、暗号化なしで動きを掴むのが分かりやすいです。

zfold pack ./dataset -o dataset.zpk
zfold list dataset.zpk
zfold extract dataset.zpk -d ./out
zfold verify dataset.zpk
覚え方: pack → list → extract → verify の 4 つを押さえると、まず困りません。
04

普通の ZIP と何が違うのか

一番大きい違いは圧縮の単位です。ZIP は基本的にファイルごと、zfold はチャンクごとにまとめて圧縮します。

ZIP

  • 各ファイルを 1 個ずつ別々に圧縮
  • 1 ファイル単位で取り出しやすい
  • ファイルをまたぐ共通パターンは活かしにくい

zfold

  • 複数ファイルをチャンクにまとめて圧縮
  • 小さい類似ファイル群で圧縮率が上がりやすい
  • 一部展開でもチャンク全体を読む必要がある

ZIP: 別々に圧縮

a.html b.html c.json → zip

似たファイルが並んでいても、別のファイルとして扱われるので、共通パターンをまたいで活かしにくいです。

zfold: チャンクでまとめて圧縮

a.html b.html c.json → chunk まとめ圧縮 → .zpk

似た HTML / JSON の繰り返しをまとめて拾いやすく、小さい類似ファイルが多いほど効きやすくなります。

zfold の強み: 「小さい」「似ている」「大量にある」ファイル群では、ZIP より有利になりやすいです。
05

zfold の長所と注意点

向くデータではかなり気持ちよく使えますが、性質を知っておくと失敗しにくくなります。

長所

  • 小さいファイルが大量にあるときに強い
  • 似た内容が多いほど圧縮率が上がりやすい
  • zstd により速度と圧縮率のバランスがよい
  • verify で内容確認ができる
  • 必要なら暗号化できる

注意点

  • 1 ファイルだけ欲しくても、そのチャンク全体を読む必要がある
  • ZIP のように各ファイルが完全独立ではない
  • --threads や --chunk-size を大きくするとメモリも増える
運用で特に重要な点: 圧縮時は、各ワーカーがチャンク 1 個分の未圧縮データをメモリ上に組み立ててから圧縮します。 低メモリ環境では --threads 1 や小さめの --chunk-size が効きます。
06

チャンクサイズの考え方

zfold では、複数ファイルをある程度のサイズで区切って「チャンク」にまとめます。

たとえば --chunk-size 16777216 なら、目標として約 16 MiB ごとにチャンクを作ります。 これは目標値であって、絶対上限ではありません。単一の大きいファイルは、それだけで大きいチャンクになることがあります。

小さめにすると

  • メモリを抑えやすい
  • 一部展開の無駄が減りやすい
  • 圧縮率は少し下がることがある

大きめにすると

  • 圧縮率が少し良くなることがある
  • 圧縮時のメモリ消費が増える
  • 一部展開で読む量も増えやすい
zfold pack ./dataset -o dataset.zpk --threads 1 --chunk-size 8388608
低メモリ環境ではこのような設定から始めると安定しやすい
07

辞書ファイルとは何か

zstd には「辞書圧縮」があります。よく出る文字列やバイト列のパターンを事前に学習し、 その知識を使って圧縮する仕組みです。

似たサンプル群 → train-dict → app.dict → pack --dict で圧縮

辞書は圧縮のヒント集のようなものです。似た HTML / JSON / 設定ファイルなどで効果が出やすくなります。

辞書を使うメリット

  • 小さいファイル群で圧縮率が上がりやすい
  • 共通パターンの多いデータで特に効く
  • 同じ種類のデータを何度も固める運用に向く

効きやすい例

  • HTML の共通テンプレート
  • 同じキー構造を持つ JSON
  • よく似た設定ファイルやログ

効きにくい例

  • 画像、動画、音声
  • すでに圧縮済みのデータ
  • 種類がバラバラで共通点が少ないデータ
大きな利点: pack --dict で使った辞書はアーカイブの中にも埋め込まれるため、 展開側が別に辞書ファイルを持っていなくても解凍できます。
08

辞書ファイルはどう作るのか

辞書は train-dict で作れます。大事なのは「これから圧縮したいデータに似たサンプルを使う」ことです。

zfold train-dict ./snap1 ./snap2 ./snap3 -o app.dict --mode text

良い辞書になる考え方

  • これから圧縮したいデータに似たサンプルを使う
  • まずは --mode text から試す
  • --extensions や --include で対象を絞る

避けたいパターン

  • 設定ファイル向け辞書を画像から作る
  • 実データと無関係なサンプルで学習する
  • 種類が混ざりすぎて共通性が薄くなる
zfold train-dict ./app -o app.dict --include "config/**" --extensions ini,json,toml,yaml
09

ZIP と zfold の使い分け

どちらが常に上ではなく、何を優先するかで選びます。

zfold を選ぶとよい場面

  • 小さいファイルが大量にある
  • ファイル同士がよく似ている
  • アーカイブ全体の圧縮率を重視したい
  • 辞書を使ってさらに詰めたい

ZIP を選ぶとよい場面

  • 誰でもすぐ開ける汎用形式を優先したい
  • 1 ファイル単位の独立した取り出しやすさが欲しい
  • 圧縮済みファイルが中心で差が期待しにくい
ひとことで言うと: zfold は「汎用交換フォーマット」というより、 「似た小ファイル群を効率よくまとめるための専用寄りツール」と考えると分かりやすいです。
10

パスワード保護と verify

必要なら暗号化でき、作成後は verify で壊れていないか確認できます。

暗号化の基本

zfold pack ./dataset -o secure.zpk --password-prompt
  • チャンクデータ、埋め込み辞書、index が暗号化される
  • ヘッダとフッタは形式判定のため平文のまま

verify の意味

zfold verify dataset.zpk
  • 構造が壊れていないか確認する
  • 各ファイルの内容が一致しているかも確認する
  • バックアップ用途では pack 後に回すと安心
11

よくある使い方

最初は単純に始めて、必要になったら辞書や暗号化を足すのがおすすめです。

とりあえずまとめる

zfold pack ./project -o project.zpk

低メモリ環境で安全寄りに

zfold pack ./project -o project.zpk --threads 1 --chunk-size 8388608

辞書を作ってから圧縮

zfold train-dict ./snap1 ./snap2 ./snap3 -o app.dict --mode text
zfold pack ./project -o project.zpk --dict app.dict
12

まとめ

zfold は、似た小ファイル群を効率よくまとめて保存するのに向いたツールです。

1
ZIP のように各ファイルを別々に圧縮するのではなく、チャンク単位でまとめて圧縮します。
2
そのため、小さいファイルが大量にある環境で圧縮率が良くなりやすいです。
3
辞書ファイルを使うと、共通パターンの多い小ファイル群でさらに効果が出やすくなります。
迷ったらこう始める: まずは辞書なしで使い、効果が欲しいデータ群に対してだけ辞書を導入するのが現実的です。
